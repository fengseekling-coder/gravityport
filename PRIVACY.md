# Privacy

Last updated: 2026-10-29

GravityPort is a local-first creative asset library. It does not operate a GravityPort cloud library, advertising system, or remote user account. Packaged desktop builds send the bounded usage signal described below, keyed by a random installation ID, through a bodyless request to the same first-party release endpoint used for update metadata; usage reporting and update-manifest parsing are separate operations.

## Data GravityPort Reads

Depending on the features you enable, GravityPort may read:

- generated media under the configured Codex generated-image root;
- matching local Codex session records used to recover Prompt and provenance, and Codex's conversation-history database (`thread_history_*.sqlite` under the Codex home folder), which GravityPort opens read-only, only for conversations it already saw images from, to read the saved path and revised Prompt of image-generation records and the user message of that turn — never image data and never other conversations. Setting `GRAVITYPORT_DISABLE_BRIDGES=codex` disables this read as well;
- media and matching `chat_history.jsonl` records under the configured Grok sessions root;
- the dedicated GravityPort Cowart canvas and the canvases of projects where Cowart was launched from Codex, found in local Codex session records from the last two weeks;
- ChatGPT web images and message-scoped context sent by the optional Chrome extension, including from conversations you used in the ChatGPT desktop app (see [ChatGPT desktop app conversations](#chatgpt-desktop-app-conversations));
- generated images and videos from Jimeng (`jimeng.jianying.com`) and Midjourney (`www.midjourney.com`) sent by the same extension, each with the site-shown Prompt text when the page exposes it (marked as unverified) and, for Jimeng, the generation-record metadata the site's own responses carry;
- user-visible generated images from Gemini, Flow, and Google AI Studio sent by the same extension; Gemini may additionally send the nearest preceding visible `user-query` within the generated image's local message structure, Flow may send one uniquely anchored visible Prompt card, and AI Studio may send the nearest preceding visible user Prompt turn in the same chat session. Each is marked as unverified. On AI Studio, images the user uploaded into one generation block (the consecutive user turns a generated result belongs to) that the page has rendered are also sent, but only as reference attachments of that block and only when the block's generated media is captured;
- the ChatGPT desktop app's local state file `.codex-global-state.json` in the Codex home folder (by default `~/.codex`), read only for the ChatGPT conversation ids of desktop-app chats and the id of the last prompt sent in each, so the Web Capture extension can capture images from those conversations.

GravityPort does not intentionally scan Downloads, Desktop, unrelated project folders, arbitrary browser pages, or source roots outside the documented allowlists.

## Data GravityPort Stores

The selected local GravityPort library can contain:

- original image or video bytes;
- WebP previews and thumbnails;
- Prompt and user-message text;
- hashes, dimensions, timestamps, source paths, source type, model/tool information, and provenance;
- version relationships, tags, archive state, and group metadata;
- for web capture, provider/page URL, capture time, capture mode, extension version, Prompt provenance/source/scope, a GravityPort-derived Prompt-priority value used only to prevent lower-quality provider fields from overwriting better ones, observed generation status when exposed by the page/runtime, and bounded source-occurrence history; ChatGPT additionally records conversation/message identifiers, the conversation title shown by ChatGPT (used to name the conversation's stack), and observed image-tool call, generation-call, response, or provider-asset identifiers when those values are explicitly present in the page/runtime data and, when the live page stream exposes it, the Prompt text of the image-tool call (what ChatGPT's chat model sent to the image generator), stored separately from the caption Prompt;
- generation events separately from deduplicated media assets. A generation event can contain a GravityPort-created `capture_context_id`, provider runtime identifiers when observed, a verification level, Prompt fields and scope, observed generation status, references, and evidence. A GravityPort capture-context ID is never represented as a provider generation-call ID;
- for ChatGPT desktop app capture, a small `.chatgpt-desktop-sync.json` file in the library folder holding, for at most 200 conversations, the conversation id, the times it was last used and last synced, a retry count, a hand-out expiry time, and a truncated SHA-256 hash of the id of the last prompt sent in it — never prompt text.

Reference images identified by Web Capture are stored as private generation-record attachments under the selected GravityPort library. They are content-hash deduplicated and may be linked into the subsequent generated asset's recipe snapshot, but they are not ordinary assets and therefore do not appear in the gallery, search, recent items, or asset totals. GravityPort does not infer the purpose or rights of a reference from its pixels. When a reference's bytes are identical to a media file the library already manages, the attachment may be stored as a hard link to that original so the bytes occupy disk space once; deleting the asset or the attachment independently leaves the other fully readable, and on filesystems without hard-link support a standalone copy is stored instead.

A recipe may record rights declarations for the reference images it used — copyright state, portrait-consent state, redistribution state, an attribution string, and permitted or forbidden purposes. These can only be attached through the MCP tools `asset_create` and `asset_update_metadata`; the app interface has no input for them. An attribution name can identify a third party, so treat it as personal data. Every field starts at `unknown`; GravityPort never infers consent.

The library is stored on the user's machine. GravityPort does not upload it to a GravityPort-operated service.

User-initiated exports of group metadata (the sidebar group context-menu "Export Group" JSON download) stay metadata-only: the exported file contains file names, Prompts, tags, groups, categories, ratings, business fields, source types, and timestamps, and the export strips every local file path and directory (managed originals, previews, import source paths), every `/library/...` URL that only resolves against the local GravityPort server, and web-capture page/media links such as `page_url` and `source_media_url`, so the file can be shared without disclosing your user name or directory structure. Fields are dropped by name only — any field, including a business field, whose key ends in `_path`, `_url`, or `_dir`, or is named `path` or `prompt_file`, is dropped, while all other fields are kept verbatim.

## AI assistant (MCP)

The GravityPort MCP server does not run on its own: an AI assistant can connect to your library only after you paste the ready-made configuration from Settings → Connect into Claude Desktop, Claude Code, or Codex. A connected assistant can search and read assets — including Prompts, source and provenance details, and local file paths — and can add images to the library. Once that content has been handed to the assistant, it is processed under that AI service's own privacy policy and may be sent to its servers. To keep an assistant from reading the library, remove the GravityPort entry from that assistant's MCP configuration.

## Usage Metrics (Random Installation ID)

Desktop builds send minimal usage metrics, keyed by a random installation ID, so the project can measure whether releases are actually being installed and retained. The ID cannot identify you on its own, but it is a fixed number for the same installation, so strictly speaking this data is pseudonymous rather than fully anonymous. This telemetry is limited to the bounded fields below and is not exposed as an in-app preference; it can be disabled locally by launching GravityPort with the `GRAVITYPORT_DISABLE_TELEMETRY=1` environment variable, for example:

- macOS, for one launch: run `GRAVITYPORT_DISABLE_TELEMETRY=1 /Applications/GravityPort.app/Contents/MacOS/GravityPort` in Terminal (use `MOSA.app/Contents/MacOS/MOSA` for an install that still carries the old name). To cover launches from the Dock or Finder until the next restart, run `launchctl setenv GRAVITYPORT_DISABLE_TELEMETRY 1` and then reopen the app.
- Windows: run `setx GRAVITYPORT_DISABLE_TELEMETRY 1` once in Command Prompt or PowerShell, then start GravityPort again. The setting applies to every later launch for your user account; remove it in System Properties → Environment Variables.

This variable name works in GravityPort 0.3.3 and later. Versions 0.3.2 and earlier recognize the switch only under its earlier name `MOSA_DISABLE_TELEMETRY`; update the app first, or use that name with an older version.

GravityPort stores a random UUID in Electron's local `userData` directory. The UUID is generated by GravityPort and is not derived from a device serial number, account, filesystem path, hardware fingerprint, Prompt, asset, or source-tool identifier.

Every desktop launch makes sure this UUID exists: it is created locally on the first launch and reused unchanged afterward; the current interface does not display it. When telemetry is disabled (`GRAVITYPORT_DISABLE_TELEMETRY=1`), or in an unpackaged development run or a QA run, the UUID is only stored locally and is never sent. Every packaged build sends it — including a package built by yourself from source. The set of reported fields is unchanged.

Packaged GravityPort Desktop sends at most one successful usage report per calendar day in the `America/Los_Angeles` time zone: a bodyless HTTPS request to `https://gravityport.azhuilab.com/releases/gravityport/latest.json` containing the following bounded fields. Versions 0.3.1 and 0.3.2 send this request to the earlier address `https://mosa.azhuilab.com/releases/gravityport/latest.json`, and versions released before the rename send it to `https://mosa.azhuilab.com/releases/latest.json`; all of these addresses are received by the same GravityPort-operated service. While the app remains open, it re-checks eligibility every 15 minutes and tries again when the previous attempt did not succeed. This usage request is independent of where the installer was obtained (for example, the GravityPort website, GitHub, or a directly shared package):

- event type: `first_launch` or `daily_active`;
- telemetry protocol version: `2`;
- the random installation UUID;
- GravityPort version;
- operating-system family: macOS, Windows, or other;
- CPU architecture such as `arm64` or `x64`.

GravityPort does not attach library contents, asset counts, Prompt text, filenames, local paths, browser history, provider conversation identifiers, email addresses, names, or account data to this request. A failed usage request is not counted as a successful usage report. Manual update checks do not create extra activity reports. Upgrading from the previous 24-hour protocol permits one report under the new protocol while preserving the existing installation UUID.

The GravityPort website, installer downloads, update manifests, usage metrics, and feedback are provided by Cloudflare (Pages, Workers, R2, and D1). Requests pass through Cloudflare's network, so Cloudflare sees IP addresses as the network operator, and Cloudflare's own privacy policy applies. GravityPort does not store IP addresses, and the Workers log feature is disabled on the GravityPort Workers (their logs would record full request URLs, and usage-request URLs contain the installation ID).

Usage metrics are recorded as one row per installation ID — first-seen and last-seen times, platform, CPU architecture, version, and first-launch flag — plus one daily-active row per day and installation. Installations that have not been seen for 90 days are folded into cumulative totals and their rows are deleted; daily-active rows are deleted after 32 days (the trend window is 30 days). Cumulative per-platform and first-launch counters are kept long-term but contain no installation IDs.

Website visits are counted daily only: the page path, the referring site's hostname (never the full URL), the country, and the device class (desktop, mobile, or tablet). No IP addresses are stored and no cookies are set; the browser user agent is read to classify the device and to exclude crawlers, then discarded.

Downloads are counted daily per file and per source label. A download URL can carry a short campaign label such as `ref=reddit_codex` so aggregate download traffic can be attributed to the page or creator that referred it; any non-empty label counts as-is, and everything else — including a plain download URL — counts as "direct".

The legacy `mosa.azhuilab.com` addresses used by versions 0.3.2 and earlier are now received by the same Cloudflare-hosted service. The usage data is visible only to the developer, through a logged-in admin page.

## Desktop application updates

GravityPort Desktop reads `https://gravityport.azhuilab.com/releases/gravityport/latest.json` about 2 minutes after the app starts and then every 4 hours while it stays open, and when you check for or install an update by hand; if a previous launch already staged a pending update package, the manifest is also read once immediately at startup (versions 0.3.4 and earlier checked only when the window opened and more than 24 hours had passed since the last check). Versions 0.3.2 and earlier read the same files from the earlier host `mosa.azhuilab.com` (versions released before the rename read `releases/latest.json` there). Update checks and update downloads go through the operating system's network and proxy settings. Only the usage request carries the installation ID; reading the update manifest and downloading an update do not. When a newer version is available and the app can update itself, macOS and Windows builds download in the background only the platform-specific update artifact advertised by that manifest from `https://gravityport.azhuilab.com/downloads/` (`https://mosa.azhuilab.com/downloads/` for 0.3.2 and earlier). GravityPort does not attach your library contents, images, videos, Prompts, provenance records, search queries, library paths, or Visual Pack embeddings to the update download. Update files are staged locally under Electron `userData`, verified by declared byte size and SHA-256, and used only to replace the application itself, which happens only when you choose **Restart to update** (versions 0.3.4 and earlier downloaded only after you chose **Download and update**); the library folder (`MOSA Library`, or `GravityPort Library` for new installs) and its original assets remain outside the application replacement transaction.

## No model downloads

Local visual search is not offered: the feature and its optional Visual Pack were removed. GravityPort does not download any model, and on startup it deletes the leftover Visual Pack and visual index data earlier versions kept under Electron `userData` (never your library folder).

## Optional C2PA helper download

C2PA Content Credential export can use an optional `c2patool` helper pack. The desktop installer component is implemented and tested, but no desktop UI entry point ships it to end users yet; when a future release wires that entry point, this section describes exactly what will happen. GravityPort reads the signed first-party release manifest used by application updates — signature verification is mandatory in code, not optional — and downloads the platform-specific helper only from `https://gravityport.azhuilab.com/downloads/helper-packs/c2patool/`. These requests do not include your images, videos, Prompts, provenance records, library paths, search queries, signing keys, certificates, or credentials. The downloaded helper is verified locally by pinned file sizes and SHA-256 hashes before it becomes active.

GravityPort does not download `c2patool` directly from GitHub on end-user machines. Upstream binaries and license files are consumed only by GravityPort's release preparation process, then redistributed as a pinned first-party helper pack.

## Web Capture Chrome Extension

The optional extension:

- defaults automatic capture to off for a new installation and opens its settings page so the user can review the capture disclosure before enabling it; upgrades preserve the user's existing local preference;
- runs only on the ChatGPT, Gemini, Flow, Google AI Studio, Jimeng, and Midjourney domains declared in its manifest;
- observes ChatGPT page and generation-response data to associate an image with the correct message-scoped Prompt and event-scoped conversation identifier and, when an image-generation result follows a user turn containing uploaded images, may archive those uploads as private reference attachments before the generated asset; provider asset identifiers are retained per observed reference usage when available, so a later generation can be compared against earlier Generation Events without turning that comparison into a confirmed relation;
- reads, while a ChatGPT conversation is open in a tab — one you opened, or one the extension opened for ChatGPT desktop app capture (described below) — the structure of the conversation data the page itself loaded: the message order, roles, and image file ids of the displayed branch, so GravityPort can label which turn each archived image belongs to. Only identifiers and numbers are reported: the conversation id, the user-message id of the producing turn, the turn index and total turn count, and image file ids. This turn report never contains conversation text, prompts, titles, or image or download URLs, and never covers edited-away branches. The same structure is sent at most once per browser session per conversation, only to the paired loopback GravityPort, and not at all without a paired token;
- reports the title of the ChatGPT conversation open in the tab, together with its conversation id, so GravityPort can name the stack of images captured from that conversation. The title is read from the page title or from the open conversation's sidebar entry; placeholder titles such as "New chat" are skipped, and it is capped at 200 characters. The title is also attached to images captured from that conversation. It is reported, while the extension is paired and automatic capture is on, when the conversation is opened, when its title changes, and when automatic capture is switched on; with automatic capture off it is not reported on its own, though manual saves still carry it. GravityPort keeps it only when it already holds images from that conversation; otherwise it is discarded;
- records ChatGPT web observations as `observed`, not as provider-API-verified provenance. GravityPort may locally score relation candidates from reference identity, modification-like user instructions, same-conversation order, and timing, but these remain `inferred` candidates until the user confirms or dismisses them; message order alone never creates a parent/child generation relation;
- may fetch generated image and supported video bytes from the OpenAI-, Google-, Jimeng-, and Midjourney-hosted asset domains declared in its manifest; redirect destinations are re-validated against the same media-host allowlist, and the original plus final media URL may be retained as local provenance evidence. These media downloads are made by the browser itself, so the browser attaches the provider site's own cookies to them; the extension does not read, copy, or store those cookies;
- sends captured data only to the configured loopback GravityPort address;
- receives its Web Capture Token through a loopback pairing request that GravityPort Desktop accepts only from the two fixed allowlisted GravityPort extension origins; Desktop pairing is automatic and silent, while headless CLI runtimes keep pairing disabled by default unless their owner explicitly opts in;
- stores the GravityPort address, Web Capture Token, auto-capture preference, and a bounded retry queue for unresolved capture jobs in `chrome.storage.local`, not synchronized storage. The queue is retried by a Chrome alarm and is removed after GravityPort acknowledges the capture or after its bounded retention period. Later terminal status or higher-quality Prompt metadata updates the existing queued job rather than creating an independent stale replay. While a ChatGPT desktop app conversation is being captured, the current job (conversation id, window and tab ids, start time) is kept in `chrome.storage.session`, which Chrome holds in memory and clears when the browser exits;
- reports a bounded retry-queue diagnostic snapshot to the paired loopback GravityPort runtime so the desktop Settings view can show pending/retrying capture work. This snapshot contains at most 20 queue entries and is limited to a local capture key, provider, media kind, Prompt-status label (not Prompt text), generation-status label, queue timestamps, retry-attempt count, and the bounded local error message. It also carries the extension's version number. It does not include Prompt/user-message text, page URLs, media URLs, cookies, account identifiers, or captured media bytes. The runtime keeps this diagnostic state in memory; it is refreshed by the extension and is not a second delivery queue. The same status request also tells GravityPort whether the extension can take a ChatGPT desktop app conversation right now (a true/false flag), and GravityPort's reply can carry one conversation id for it;
- accepts a local retry-request counter from GravityPort Desktop. The counter does not contain capture content and does not move ownership of queued jobs into the desktop runtime; the extension remains the only component that replays its durable queue;
- temporarily stores the captured media needed by queued jobs in the extension's local IndexedDB, so a capture made while GravityPort is closed survives an expired provider link. This covers page-local `blob:`/Base64 media and, from extension 0.15.38, provider images the page already loaded or that the extension downloads once at capture time; stored media is capped at 512 MB in total, oldest first out. Image media is stored as a Blob referenced by the retry queue; large page-local videos are stored as bounded ordered Blob chunks rather than one in-memory object. These records are deleted after GravityPort acknowledges the capture, when the user/extension aborts the transfer, or when the associated bounded retry job expires or is evicted;
- transfers large page-local generated videos to the extension worker in bounded chunks and later sends the queued chunks to GravityPort through its local upload-session endpoints rather than one whole Base64 JSON message. Remote HTTPS videos continue to stream directly to the GravityPort upload session without being retained as one whole video in extension memory;

Its manifest host permissions are limited to the following explicit hosts/patterns: `chatgpt.com`, `chat.openai.com`, `*.oaiusercontent.com`, `images.openai.com`, `*.blob.core.windows.net`, `gemini.google.com`, `labs.google`, `flow.google.com`, `aistudio.google.com`, `*.googleusercontent.com`, `*.ggpht.com`, `storage.googleapis.com`, `generativelanguage.googleapis.com`, `flow-content.google`, `jimeng.jianying.com`, `*.byteimg.com`, `*.jimeng.com`, `*.vlabvod.com`, `www.midjourney.com`, `cdn.midjourney.com`, plus loopback `127.0.0.1` and `localhost` for delivery to GravityPort. The Azure Blob, ByteDance (`byteimg.com`, `jimeng.com`, `vlabvod.com`), and Midjourney CDN hosts are used for provider-served media bytes and are not GravityPort-operated endpoints. Its API permissions are `storage`, `contextMenus`, `alarms`, and `unlimitedStorage`:

- `storage` saves the GravityPort address, the Web Capture Token, the auto-capture preference, and the bounded retry queue in `chrome.storage.local`, and the in-progress ChatGPT desktop app capture job (conversation id, window and tab ids, start time) in `chrome.storage.session`, which Chrome holds in memory and clears when the browser exits;
- `contextMenus` provides the right-click menu items for saving an image or a video to GravityPort by hand;
- `alarms` drives the timer that retries queued captures;
- `unlimitedStorage` lets the extension's local storage hold the media bytes of queued captures (capped at 512 MB in total) so an expired provider link does not lose them while GravityPort is closed.

The minimized windows used for ChatGPT desktop app capture are opened and closed through `chrome.windows`, which needs no additional permission.

For captured videos, GravityPort may store media dimensions, MIME/type information, byte size, and `durationSeconds` when the provider-visible media metadata exposes a usable duration. This field is local provenance metadata and is not transmitted to a GravityPort cloud service.

When updating from an earlier prerelease extension, existing settings may be read once from Chrome synchronized storage, copied to local storage, and removed from synchronized storage. The known prerelease development Token is discarded rather than migrated.

The extension does not request or store an OpenAI API Key or ChatGPT password. It operates inside the user's existing browser session, so each provider and its asset hosts remain governed by their own privacy terms.

For ChatGPT late-caption recovery, the page-world hook may make a same-origin request for the currently open conversation using the browser session already available to that page. The page-world hook does not read, copy, store, post, or replay ChatGPT Authorization headers or related authentication request headers. The only place the extension handles a ChatGPT credential is the check described under [ChatGPT desktop app conversations](#chatgpt-desktop-app-conversations): there the background worker obtains a short-lived access token from `https://chatgpt.com/api/auth/session` and uses it for one request to `chatgpt.com`, without storing it or sending it anywhere else. If the same-origin request is not sufficient, the image remains archived and the Prompt may remain unavailable.

On Gemini (`gemini.google.com`), it may additionally capture only the nearest preceding rendered `user-query` associated with a visible image inside a `model-response`. It skips inputs, editors, hidden content, unrelated page regions, credentials, cookies, and API keys. This text is marked `provider-visible-prompt` and is not verified as the prompt actually executed for generation.

On Google AI Studio (`aistudio.google.com`), it may additionally capture only the nearest preceding rendered user Prompt turn within the same conversation section (the page element classed `chat-session-content`) as a visible generated image. It skips controls, inputs, editors, hidden content, model thoughts, other sessions, cookies, credentials, and API keys. This text is marked `provider-visible-prompt` and is not verified as the prompt actually executed for generation. Images the user uploaded into the same generation block (the consecutive user turns the generated result belongs to) and that the page has rendered at least once are remembered only in the page's memory and sent to the local GravityPort as reference attachments of that block, only when that block's generated media is actually captured; if a reference renders only after the block's media was already captured, the already-captured media is re-reported once under the same block id so the references can be attached.

On Flow (`labs.google` / `flow.google.com`), it also may capture the one visible Prompt card structurally associated with a visible generated-image group, but only when the card has a unique nearby `Reuse Prompt` control. This text is marked `provider-visible-prompt`, is not verified as the prompt actually used for generation, and is never collected from an input, editor, hidden content, cookies, credentials, or the page as a whole.

On Jimeng (`jimeng.jianying.com`), the extension observes, read-only, the JSON responses the site itself receives from its own `/mweb/v1/` endpoints (generation-status polls and history listings). From those responses it keeps only the signed media URLs of generation records created after the extension started on the page, the record/item identifiers, the site-shown Prompt text and model-name fields when present, media dimensions, and reference-image URLs when present. Responses about records that predate the extension's start are used only to remember those records as already-existing history (a baseline), so they are never auto-captured; the user can still save any item manually from the right-click menu. The signed media URLs expire, so the bytes are downloaded once at capture time, with or without cookies as the site requires; the extension never modifies the site's requests, and never stores or reports cookies, account identifiers, or session tokens from these responses. Prompt text captured this way is marked `provider-visible-prompt` and is not verified as the prompt actually used for generation. The extension also observes the site's own delete call (`/mweb/v1/remove_history`), read-only, so a work you delete on the site can be moved to the GravityPort trash as well (the moved asset then sits in the GravityPort Trash, kept for 90 days and restorable until then, after which it is permanently deleted like any other trashed asset; assets you favorited, rated, grouped, or tagged stay put): when the site confirms a deletion, only the deleted work item ids from that request body are forwarded to GravityPort — request headers, cookies, URL query parameters, and every other request body are not read or sent. This deletion sync can be turned off in GravityPort settings.

On Midjourney (`www.midjourney.com`), the extension reads the rendered `/imagine` feed: preview images on `cdn.midjourney.com`, the prompt text shown on the surrounding job card, and `<video>` elements the page renders. Full-size PNGs live at the same CDN path as the preview WebP but are cookie-gated, so the extension's background worker downloads them with the browser's cookies; when the original is unavailable the preview WebP is archived instead and the asset is recorded as `media_variant: preview`. Job cards that already exist when the extension starts, arrive in scroll-triggered batches, or arrive as three-or-more new jobs in one update are treated as history and are never auto-captured; only a fresh single job card appearing outside a scroll window is captured automatically, and any job can still be saved manually from the right-click menu. Prompt text captured this way is marked `provider-visible-prompt` and is not verified as the prompt actually used for generation.

## ChatGPT desktop app conversations

The ChatGPT desktop app (the same app that now hosts Codex) does not save chat images or chat text on your computer, so GravityPort cannot import them from disk. Instead, GravityPort notices which desktop conversation you just used and asks the Web Capture extension to capture that conversation from `chatgpt.com` in your browser.

While the Codex source is enabled, the local GravityPort service checks the desktop app's state file `.codex-global-state.json` in the Codex home folder (`$CODEX_HOME`, by default `~/.codex`) about every 10 seconds. From that file GravityPort uses only two things: the ChatGPT conversation ids that the desktop app's chats are bound to, and, for each conversation you sent a prompt in, the id of the last prompt message. Prompt text, the composer history, account details, and the rest of the file are not used or stored. A conversation counts as used when it first appears in the file or when the id of its last prompt changes. The first time GravityPort reads the file, every conversation listed there is marked once, so existing desktop chats get a single catch-up check.

GravityPort keeps its progress in `.chatgpt-desktop-sync.json` in the library folder: for at most 200 conversations, the conversation id, the times the conversation was last used and last synced, a retry count, a hand-out expiry time, and a truncated SHA-256 hash of the last prompt message id — not the id itself and no prompt text. The file never leaves your computer.

A conversation is handed out only after it has been quiet for 90 seconds, one at a time, in GravityPort's reply to the paired extension's regular local status report (about once a minute), and only to an extension that has automatic capture turned on and no desktop sync window already open. The extension reports back only the conversation id and an outcome (`captured`, `no-images`, `failed`, or `timeout`); a conversation is tried at most three times each time it is used.

The extension first checks whether the conversation contains a generated image. Its background worker asks `https://chatgpt.com/api/auth/session` for the access token of the ChatGPT account your browser is signed in to, using the browser's existing ChatGPT cookies, and sends that token once, as the Authorization header of a single request to `https://chatgpt.com/backend-api/conversation/<id>`, because ChatGPT does not answer this request with cookies alone. The token is held in memory for that request only; it is not stored and is never sent to GravityPort or to any host other than `chatgpt.com`. The rest of the session response, such as your account name or email address, is not used. The conversation response is examined only for whether a non-user message contains an image; nothing from it is stored or sent to GravityPort.

If the conversation contains no generated image, the extension reports `no-images` and opens nothing. Otherwise — or when the check could not be completed — it opens `https://chatgpt.com/c/<id>#gravityport-desktop-sync` in a new minimized, unfocused browser window, one window at a time; the window may briefly appear in your taskbar or window list. The page is then captured exactly like a ChatGPT conversation you reopened yourself, with the data described under [Web Capture Chrome Extension](#web-capture-chrome-extension): images, your messages as Prompt context, conversation and message identifiers, turn structure, and the conversation title. ChatGPT's live-only image caption and image-tool Prompt are not available this way. Once capture has been quiet for 10 seconds (at least 20 and at most 110 seconds after the page loads), the extension closes the window. A window still open after about 150 seconds is closed and reported as timed out, and closing the window yourself ends that attempt.

These requests use your browser's own ChatGPT session and remain governed by OpenAI's terms, as if you had opened the conversation in the browser yourself; GravityPort itself does not contact OpenAI. If the browser is signed in to a different ChatGPT account than the desktop app, the conversation cannot be read and nothing is captured.

To stop this, turn off automatic capture in the extension, or disable or remove the extension; GravityPort then hands out no conversations. To stop GravityPort from reading the desktop app's state file at all, disable the Codex source with `GRAVITYPORT_DISABLE_BRIDGES=codex`, which also stops Codex image import. Deleting `.chatgpt-desktop-sync.json` resets the tracking; GravityPort recreates it and checks every listed conversation once more.

## Pinterest connection (not yet available)

GravityPort Desktop can optionally connect to your Pinterest account so you can browse your own boards and Pins inside the app. The feature is implemented but not yet available: the sidebar entry stays marked as unavailable until Pinterest approves production API access, and GravityPort does not access Pinterest at all until you connect.

Once connected, the app reads the following through the official Pinterest API with read-only scopes: your Pinterest username; the name, description, Pin count, and cover of your boards, including secret boards; and the title, description, link, and image addresses of the Pins on those boards. This content is shown live on your computer only. It is not saved into the GravityPort library and is not uploaded to GravityPort-operated servers. To avoid repeated requests, the app keeps responses in an in-memory cache for at most 5 minutes and clears it when you disconnect or quit the app. Pin images load directly from Pinterest.

Access tokens are stored only on your computer, as an atomically written, permission-restricted (mode 0600) file in Electron's local `userData` directory. During authorization, the GravityPort-operated service only forwards the authorization code or refresh token, together with the app secret, to Pinterest to obtain tokens, and returns the result directly to your computer; the app itself never holds the app secret. This relay runs on Cloudflare Workers, stores no authorization codes or tokens, and does not write them to logs.

You can disconnect Pinterest at any time in GravityPort settings, which deletes the token file stored on your computer. You can also revoke GravityPort's access under the authorized apps in your Pinterest account settings.

## Feedback

The app never collects feedback in the background: feedback is submitted only when you press **Send** on the feedback page in GravityPort settings. The app forwards one request to the first-party feedback collection service at `https://gravityport.azhuilab.com/api/feedback` (`https://mosa.azhuilab.com/api/feedback` in 0.3.2 and earlier).

When you press **Send**, the app submits:

- the feedback text you wrote (at most 5000 characters);
- a contact address you optionally fill in, used only to reply to you (at most 200 characters);
- the interface language (Chinese or English);
- the feedback type you chose (bug, idea, or other), app version and build commit identifier, operating system and its version, and CPU architecture type;
- if you tick **Include diagnostic log** (unticked by default), the app's recent runtime log.

The diagnostic log is a bounded in-memory ring buffer of recent warnings, errors, and informational lines from the local GravityPort service, the desktop main process, and the interface itself (renderer console errors are included); it is kept in memory only and is not written to a log file. You can review its full content in the app before sending — what you see is exactly what is sent. Usernames in library and home file paths, tokens and other long secrets, and email addresses are masked, and any line that might contain prompt or instruction text is removed entirely. The text is redacted again when the request is submitted, and the submission is capped in size.

The app does not send and does not store with the feedback: the installation ID, your assets, prompts, or the library location. The local log records only the outcome status of a submission, never its content.

Feedback is stored in a Cloudflare database and is visible only to the developer through a logged-in admin page; it is used only to reply to you and to improve the product, not for advertising, and is never shared with third parties. IP addresses are not stored with the feedback content — an IP is used only in memory, temporarily, to prevent submission abuse — and the total amount of feedback that can be stored is capped. To have feedback you sent deleted, write to [fengseekling@gmail.com](mailto:fengseekling@gmail.com) and mention roughly when you sent it.

## Network Boundary

The GravityPort service binds to `127.0.0.1` and is not designed for public exposure. GravityPort does not add remote synchronization. The desktop shell's only GravityPort-operated analytics signal is the bounded usage metadata, keyed by a random installation ID, sent through the separate HTTPS request described above.

The outbound connections described in the sections above are: the update and usage endpoints under `gravityport.azhuilab.com` (`mosa.azhuilab.com` in 0.3.2 and earlier); the Pinterest authorization relay under `gravityport.azhuilab.com` together with Pinterest's own authorization and API endpoints when you connect Pinterest — once connected, Pin images also load directly from Pinterest's `i.pinimg.com`; and the feedback collection service when you press **Send** on the feedback page. On Windows, for some system languages the embedded browser may additionally download spell-check dictionary files from Google; only dictionary files are downloaded, nothing you type is sent, and Chinese-language systems do not download one. None of them carries your library contents, and Pinterest browsing results are not sent anywhere by GravityPort. The Web Capture extension's requests to `chatgpt.com` for ChatGPT desktop app conversations are made by your browser with your own ChatGPT session; GravityPort itself does not contact OpenAI.

Codex, ChatGPT, Grok, Cowart, Chrome, Pinterest, and any AI or image-generation provider used before an asset reaches GravityPort are separate products. Their own network behavior and privacy policies still apply.

## User Control

- In the desktop app, choose **Settings → Storage → Change** (next to Storage location) to move the local library to an empty folder. GravityPort copies the existing assets and metadata, switches the saved location only after the copy succeeds, and then restarts.
- `GRAVITYPORT_LIBRARY_DIR` remains an explicit runtime override. When it is set, it takes precedence over the saved desktop location and the in-app move control is disabled.
- Disable web capture by disabling or removing the extension. Turning off its automatic capture stops automatic capture and ChatGPT desktop app capture, and the separate conversation-title reports, while manual saves still work. GravityPort Desktop creates its own Web Capture Token in Electron `userData` and pairs automatically, so leaving `GRAVITYPORT_WEB_CAPTURE_TOKEN` unset does not disable web capture there; a standalone `npm start` runtime keeps web capture disabled while `GRAVITYPORT_WEB_CAPTURE_TOKEN` is unset.
- Disable a source bridge by not configuring or running the corresponding source tool, or by listing it in `GRAVITYPORT_DISABLE_BRIDGES` (comma-separated: `codex`, `grok`, `cowart`, `cowartDiscovery`). Disabling `codex` also stops GravityPort from reading the ChatGPT desktop app's state file.
- Update checks and update downloads happen automatically in packaged desktop builds and cannot be turned off; they do not carry the installation ID. The usage report is the only related request that can be disabled, with `GRAVITYPORT_DISABLE_TELEMETRY=1`.
- Pinterest stays disconnected until you connect it in Settings → Connect; disconnecting deletes the tokens stored on your computer, and until then GravityPort never accesses Pinterest.
- Nothing is submitted through the feedback page until you press **Send** there; leaving **Include diagnostic log** unticked sends no log.
- Back up the library before migration, repair, or manual removal.
- Do not commit the library, Tokens, Prompts, session records, or generated media to the source repository.
- The `GRAVITYPORT_*` environment variable names in this document apply to GravityPort 0.3.3 and later. Versions 0.3.2 and earlier read the same switches under their earlier `MOSA_*` names (for example `MOSA_DISABLE_BRIDGES`).

GravityPort archive actions are organizational and do not promise secure erasure. Filesystem backups, browser data, source-tool histories, and copied media must be managed separately.
