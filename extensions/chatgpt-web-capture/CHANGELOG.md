# GravityPort Web Capture 更新记录

本文件按版本记录扩展抓取逻辑的细节变化，最新版本在前，内容原先写在扩展 README 中。更新的版本和整个产品的变更见仓库根目录的 [CHANGELOG.md](../../CHANGELOG.md)。

## 0.15.44

自 `0.15.44` 起，GravityPort 没开或拒收时，页面不再反复重发同一张图：后台只要已经把票据放进扩展自己的离线队列，就回「已排队」，页面不再自动重发、也不再重新下载原图；GravityPort 打开后由队列补投。投递失败按种类分三类：没有状态码、超时、408 / 425 / 429 / 5xx 为可重试，票据留在队列里；GravityPort 回 401 / 403（配对坏了）或本地没有 Token 的票据也留着，重新配对后补投；GravityPort 回其他 4xx、超过大小上限、或媒体网址 403 / 404 / 410 为永久错误，票据当场移出队列。视频上传的 begin、分块、commit 失败也按同一规则分类，commit 被拒时页面收到失败。正文下载有空闲超时（图片 15 秒、视频 45 秒，超时只看读不到新数据的时间），一张卡住的票据不再拖住整条队列。实时投递进行中时，每分钟的排空会跳过同一张票据，不会同时投两次。预抓字节前先看队列：票据已有字节时不再重新下载；页面自己带字节重发同一张图时（例如 ChatGPT 先临时收、出完整图后再收），以最后一次的字节为准。ChatGPT 收到「已排队」时状态栏写「已排队 · GravityPort 打开后自动入库」，不再弹错误提示；同一张图的同一条错误只提示一次。配对改为 3 秒超时，冷启动时整轮探测失败会隔 1.5 秒再试一整轮。选项页「测试连接」遇到 Token 不匹配时，会先请扩展后台重新配对一次，成功则用新 Token 重测。Midjourney 连续出图时，已经收过的作品不再计入「一批出现 = 历史」的判断，之前只有 3 个新作品同时出现时，第 3 个会被当成历史漏收。

## 0.15.43

自 `0.15.43` 起，Google AI Studio 里上传的参考图会跟着成品一起收进 GravityPort，挂在成品的参考图里。扩展把「连续几轮用户消息 + 后面的模型回复」当成一次生成，用户轮里页面显示过的上传图片只记在页面内存里，等这次生成真的收到成品时，先把参考图发给本机 GravityPort，再发成品。只让模型看图、没有出图的，上传的图片不会发出。AI Studio 会把离视野远的轮次折叠掉；参考图如果在成品之后才显示出来（例如重新打开旧对话后往上翻），会先补发参考图，再把成品重发一次让 GravityPort 补上关联，同一组只补一次。

## 0.15.42

自 `0.15.42` 起，在即梦网站里删掉的生成作品，GravityPort 里对应的收录也会跟着移进回收站（可在回收站恢复）：页面钩子只读地认出即梦自己的删除请求（`/mweb/v1/remove_history`），在站点确认删除成功（HTTP 200 且 `ret` 为 0）后，把请求体里的作品编号发给本机 GravityPort 对号入座；请求头、Cookie、网址查询参数和其余任何请求体都不读取、不转发。在 GravityPort 里收藏、打分、分组或加了标签的素材不会被移动；早期收录时没记到作品编号的素材对不上号，保持不动。GravityPort 设置 → 连接 → 浏览器扩展里有开关（默认打开），关掉后任何素材都不会被移动。

## 0.15.38

自 `0.15.38` 起，GravityPort 没开时，扩展的待重试队列会把图片本身先存进扩展的 IndexedDB（总量最多 512MB，超出后最旧的票据先退回仅网址、没有网址的直接移除），不再只留一个可能很快过期的下载网址；只有网址、页面没取到字节的采集会在入队时趁网址最新鲜当场补抓一次，抓不到才保持仅网址。已过期的媒体网址（403 / 404 / 410）重试 3 次后按「网址已过期」放弃并移出队列，不再每分钟重试到 7 天清退；网络错误与 5xx 照旧重试。为此清单重新申请了 `unlimitedStorage` 权限（`0.15.37` 移除过；这次队列真的要长期保存字节了）。

## 0.15.37

自 `0.15.37` 起，扩展不再申请 `unlimitedStorage` 权限，也不再带开发用的采集诊断记录器：它此前只在开发版里存在，默认关闭、只能通过隐藏页面打开。采集行为不变。

## 0.15.36

自 `0.15.36` 起，关掉自动入库后，扩展不再自己上报 ChatGPT 对话标题；打开自动入库时会补报一次当前对话的标题。手动保存的素材照旧带上标题。

## 0.15.35

自 `0.15.35` 起，用户原话（`user_message`）不再带上发送时所选工具的标签：用 ChatGPT「创建图像」发出的消息，气泡里那一行单独的「创建图像」（以及繁体、英文 Create image）只要是开头或结尾的一整行就会去掉；正文里自己打的同样字样（如「@创建图像 …」）原样保留。Prompt 的取值规则不变。

## 0.15.34

自 `0.15.34` 起，桌面版对话有窗口正在采集时，扩展上报状态不再领取新的对话，免得领到的对话因为一次只开一个窗口而白白等满 5 分钟租期；GravityPort 那边也改成一次只交一段，并改为按「这段对话里最后一次提问的编号有没有变」判断哪段对话刚用过，不再把仍保留着续聊记录的旧对话一起算进去。

## 0.15.33

自 `0.15.33` 起，在 ChatGPT 桌面版（和 Codex 合在一个 App 里）直接聊天生成的图也能自动入库。桌面版不把聊天里的图存到本机，GravityPort 只从桌面版的本地状态里认出刚用过的对话号，在扩展每分钟上报状态时交给扩展（仅在自动入库打开时）。扩展先用浏览器自己的 ChatGPT 登录读一次这段对话：里面没有生成图就直接回报「无图」；有（或读不到）才在一个最小化、不抢焦点的新窗口里打开 `https://chatgpt.com/c/<对话号>#gravityport-desktop-sync`，走原有的页面采集流程。页面的采集安静 10 秒（至少 20 秒、最多 110 秒）后通知扩展关窗，并回报结果；一次只开一个窗口，150 秒没结束按超时关掉。和在浏览器里打开旧对话一样，能收到图和用户原话，Model caption 与提示词2 只在实时推送里，收不到。读对话时，后台向 `chatgpt.com/api/auth/session` 取一次登录令牌，只用于这一次请求，不保存、不发给 GravityPort；这是扩展第一次自己请求对话接口，且只针对 GravityPort 交来的桌面版对话。

## 0.15.29

自 `0.15.29` 起，扩展的名称、采集面板、提示条、右键菜单、选项页和报错信息都改叫 GravityPort；存储键（`mosaToken`/`mosaBaseUrl`）、配对标识和扩展 key 原样不动——旧扩展仍能与新版应用配对，改名后的扩展也能与旧版应用配对。

## 0.15.27

自 `0.15.27` 起，ChatGPT 消息列表里省略掉的内部节点（工具调用等）不再让整批轮次作废：某条消息的上一条不在列表里时视为被省略的内部节点；上一条在列表里但排在它后面，仍然整批不发。

## 0.15.26

自 `0.15.26` 起，适配 ChatGPT 新的对话数据格式（对话改为按时间排好的扁平消息列表加分页字段，不再是分支树）：只在一次请求就拿到完整对话时上报轮次；只返回最近几页的长对话不上报（宁可不显示，也绝不报一个错的轮次），界面退回只显示张数，往上翻页拼接是后续工作。原有分支树格式的解析保持不变。

## 0.15.25

自 `0.15.25` 起，扩展会读取**用户自己打开的** ChatGPT 对话的结构，用来给素材标注所在轮次：数据只来自页面自己请求到的当前对话 JSON，只解析当前显示分支里的消息顺序与角色（隐藏的系统消息不计入轮次），把「哪个图片文件属于第几轮」——对话编号、该轮用户消息编号、轮次序号与总轮数、图片文件编号——发给本机 GravityPort。**不读取、不上传对话文字、提示词、标题或图片地址**；编辑掉的其他分支不读取；用户上传的图和仅被引用的图不参与；插件从不自己请求对话接口，也不读取未打开的对话（更正：0.15.33 起，桌面版对话同步和迟到提示词补救会请求当前对话，见 PRIVACY.md）。同一对话的同一结构每次浏览器会话只发一次，发送失败不记住、下次打开对话自然重试，未配对 Token 时不发；同一批次超过 2000 条时整批不发（截断会让轮次总数与素材对不上）。

## 0.15.24

自 `0.15.24` 起，采集载荷会附带当前 ChatGPT 对话的标题（优先读 `document.title` 并去掉“ - ChatGPT”这类站名后缀，读不到再取侧栏当前对话项的文字；“ChatGPT / New chat / 新聊天 / 新对话”等占位标题视为无标题，且仅当图片的 conversation ID 与当前网址一致时才附带）。GravityPort 用它给还没有名字的会话堆叠自动命名；重新打开旧对话时，标题也会单独上报一次补齐（同一对话同一标题每次浏览器会话只发一次，未配对 Token 时不发），用户自己起过名的堆叠不受影响。

## 0.15.23

自 `0.15.23` 起，图生图轮次恢复收录上传的参考图：ChatGPT 把一条用户消息拆成"附件单元 + 文字单元"两个兄弟节点后，原有的选择器只能认到不含图的文字单元，参考图因此一张也收不到。现在 `:user` 结尾的 `data-chatgpt-search-unit-key` 单元与 `data-content-search-unit-key` 单元同等识别，并按同一个 turn 容器（或 unit-key 前缀）合并同一条用户消息的全部用户单元取图；取图范围仍限定在用户单元内部，同一容器里助手单元生成画廊中的图不会被误判为参考图，输入框里的附件照旧跳过。

## 0.15.22

自 `0.15.22` 起，page-hook 与内容脚本之间改用一次性移交的私有 `MessagePort` 通信，不再把通道名写在 DOM 里，页面上后注入的脚本既拿不到通道也无法伪造采集事件；同时 provider 页面的内容脚本向 background 请求设置时只拿到 `autoCapture` 一个字段，Token 不再下发到页面环境。

## 0.15.21

自 `0.15.21` 起，ChatGPT 通过流式请求（`POST /backend-api/f/conversation` 的 SSE）推送的回复改为边收边解析：按 `delta encoding v1` 的 add 与补丁事件在流中重建消息，图片的生成 ID、资源 ID 与消息 ID 在事件到达时立即绑定，页面在 `[DONE]` 之后中止请求也不再丢失整轮内容；补丁支持 append（含对象合并与 `/message/content/parts/N` 数组下标）、replace 与跨事件续接 append，遇到不认识的补丁直接忽略，单条流沿用 12MB 解析上限。旧的缓冲解析与非 SSE 的 JSON 响应路径保持不变。

## 0.15.20

自 `0.15.20` 起，画廊里没点开的图也会入库：只要某个 `blob:` 地址有文件编号映射且注册表里有该文件编号的生成证据，缩略图不再要求 `<img>` 加载完成——字节直接按 `blob:` 地址从页面内存读取，真实宽高由解码后的字节判定（仍套用"已证明生成图"的 256px 最小边），大图与缩略图共用同一 `blob:` 身份，依旧只入库一次。

## 0.15.19

自 `0.15.19` 起，ChatGPT 新版"一轮多张图"画廊（大图 + 缩略图条，页面上只有同源 `blob:` 地址、同一消息 ID 重复 N 次）不再因此全部丢失 Model caption。页面取生成图的固定链路是 `fetch /backend-api/estuary/content?id=file_X` → `Response.blob()` → `URL.createObjectURL()`；page-hook 会把"下载得到的 Blob → 文件编号 file_X"记进 WeakMap，并在 `createObjectURL` 时经既有页面通道发出 `blob-asset` 消息，内容脚本只在校验同源 `blob:` 与 `file_` 形态编号后把 `blob:` 地址补进图片身份键。绑定因此直接按文件编号对上实时推送里各图的 caption，不再依赖消息 ID（消息 ID 在多次生成时按设计放弃绑定）；对应关系只发送 `id` 这一个参数，`sig`/`p`/`cid`/`ts` 等签名或令牌参数不读取、不保存、不发送。批量请求（`batch_requests` 多条）下的"提示词2"（`generation_request_prompt`）保持留空：页面上没有能把某张图可靠对应到第几条请求的证据（final 消息中途的图片顺序是完成顺序），宁可缺也不配错。

## 0.15.18

自 `0.15.18` 起，新会话在地址栏尚未出现 `/c/<conversationId>` 时，实时 transport 中已经观察到的 conversation identity 会先作为当前会话身份使用；随后 URL 获得同一 ID 只做身份补全，不再清空 live-only 的 Model caption、ImageGen request Prompt 或 generation registry。ChatGPT 的 `blob:` 输出若所在 DOM wrapper 同时列出 displayed/commentary 等多个 message ID，只有这些 ID 全部能唯一归并到同一个 Generation Attempt 时才允许绑定；跨 retry/失败 Attempt 或存在未知 message ID 时仍保持 fail-closed。
